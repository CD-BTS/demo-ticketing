## 실제 자동 물리적 해제

스케줄러를 활성화한 상태에서 다음 순서로 검증했다.

1. A의 다중 좌석 선점과 2분 늦게 생성한 별도 유효 선점을 준비했다.
2. 5분 직전까지 Clock을 이동하고 실제 스케줄러가 한 차례 실행되어도 A의 선점이 유지됨을 확인했다.
3. 정확한 만료 시각으로 Clock을 이동했다.
4. 이후 **HTTP 요청 0회, 직접 expire 호출 0회**인 상태에서 JDBC SELECT만으로 선점 EXPIRED, DB 좌석 AVAILABLE, 점유 ID 제거를 확인했다.
5. 별도 유효 선점은 HELD로 유지되었다. 물리적 해제 증명 후에만 확정 거부와 B의 재선점·재예매 요청을 보냈다.

최종 XML의 자동 복구 관측 지연은 **5127.68ms**였다. 기본 스케줄러 주기 5000ms와 SQL 폴링 지연을 포함한 관측값이며 만료 즉시 해제를 보장하는 수치는 아니다.

별도 스케줄러 테스트에서는 만료 ACTIVE 선점만 해제되고 이미 CONVERTED인 선점의 BOOKED 좌석·CONFIRMED 예매·ISSUED 티켓은 유지됨을 확인했다.

Issue #23 병렬성 회귀 테스트에서는 첫 트랜잭션이 좌석을 잠근 미커밋 상태에서 다른 좌석 요청이 **74.41ms**에 완료되었다. 이전 실행 대비 성능 비교 실험은 아니다.
